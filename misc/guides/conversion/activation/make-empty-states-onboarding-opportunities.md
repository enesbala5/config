# Treat empty states as onboarding opportunities

**Feeds stage:** audit

An empty screen is a teaching moment, not a dead end. Fill it with an
explanation of what the area is for, a preview of what it looks like with data,
one clear primary action to add the first item, and — where possible —
pre-populated example data.

Test a good empty state against dummy data: each solves blank-slate overwhelm
differently, and the right one depends on whether the examples feel real for
the product.
