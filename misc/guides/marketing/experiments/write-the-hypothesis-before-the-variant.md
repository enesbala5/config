# Write the hypothesis before you design the variant

**Feeds stage:** verify

A test is not "let's see what happens". State it as: because [observation or
data], we believe [change] will cause [expected outcome] for [audience]; we will
know this is true when [metric]. The observation is what makes the claim
falsifiable and tells you which metric to watch.

Weak: "Changing the button colour might increase clicks." Strong: "Because
heatmaps and user feedback show people cannot find the CTA, we believe a larger,
contrasting button will raise CTA clicks by 15%+ for new visitors; we will
measure click-through from page view to signup start."

If you cannot name the observation behind the change, you are guessing, and no
amount of traffic will turn the guess into a decision rule.
