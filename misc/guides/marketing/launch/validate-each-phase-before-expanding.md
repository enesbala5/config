# Validate each launch phase before expanding to the next

**Feeds stage:** plan

Treat a launch as a five-step ladder, not a one-day event, and widen the audience
only when the current phase's goal is met:

- Internal — friendly users test a demo-able prototype; validate core function.
- Alpha — landing page with early-access signup; first external validation and a waitlist; MVP works in production.
- Beta — work through the list (some free, some paid), tease the problem you solve, recruit friends, investors and influencers to test and share.
- Early access — leak screenshots, GIFs and demos; gather quantitative usage plus qualitative feedback; optionally run a product/market fit survey to refine messaging. Expand by throttling invites in batches of 5–10% or inviting everyone under an "early access" framing.
- Full — open self-serve signups, start charging, announce general availability.

Counterexample: opening the floodgates before validating core functionality with
friendly users.
