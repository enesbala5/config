# Write and render a recipe by hand

**Feeds stage:** building-sounds

A build writes a recipe; you can write or edit one yourself and render it without models. `earshot recipe --example` prints the form, `earshot recipe NAME` a cookbook recipe to change, `earshot recipe --check roar.json` checks it, `earshot make --recipe roar.json -o roar.wav` renders it (a few seconds for a hit, up to half a minute for a long layered bed). Learned designs are the best parts because they are real (`earshot sounds --search`). A layer is a catalogue design (`"sound"`) or a plain source (`"source": "noise"` with `dur` and `color`, or `"sine"` with `dur` and `hz` from 20 to 150). Layer fields include `seed`, `dur`, `pitch` (semitones, -24 to 12, as on a tape: lower is also slower and bigger), `glide`, `reverse`, `cut` ([from, to] s), `halt`, `lowpass`/`highpass` (Hz or [from, to]), `pan`, `gain`, `at`, `fade_in`/`fade_out`, `swell`, `decay`, the design's own axes, `events`, `scatter`, `level`/`bend`, `pass`, `spin`, `stretch` (0.5 to 2) and `recipe`. Whole-recipe fields: `name`, `says`, `layers` (1 to 12), `dur`, `space` (dry, booth, room, studio, hall, plate, cathedral), `kind` (`event` or `ambience` for a bed). A mistake is answered in one sentence naming the field. The same recipe works in Python (`make(recipe={...}, out=...)`), the MCP `make` tool and a spec entry.
