# Trust measurements first, then verdicts and z

**Feeds stage:** listening

LUFS, dBTP, LRA, dBFS, ms, Hz are exact measurements (BS.1770 meter, spectrum, envelope) — use them for levels. z (match/rank/find/describe tags) is how far a description stands out among the 322 vocabulary descriptions scored on the same sound: z >= 3 strong, 2.5-3 plausible, 2-2.5 weak, < 2 no match. A `strong` verdict on 125 held-out real recordings was the right kind of sound 98 % of the time and the exact variant 61 %: `earshot match key.ogg "a deep thocky mechanical keyboard press" --alts "a clicky blue switch keyboard" "a mouse click"` → `strong (z +3.7; would rank #2 among 322 vocabulary descriptions)`. p_vs_alts is an uncalibrated forced choice between your query and alternatives: it only says which wording fits best, judge by z. Cosine is raw CLAP similarity — never a probability; compare only for the same sound and query. AudioSet labels (0..1) are independent per-class probabilities, good for broad classes, hearing only up to 8 kHz. p_real/verdict is strong evidence, not proof: read its evidence list; thresholds differ for clips (<= 6 s) and long files. digital_silence_frac is weak alone (edit/fade padding is common). typicality z: >= -1 fits the reference set, < -2 outlier. Sync offset_ms/chance: trust when well above chance. critique status is a range, not a target — ok means inside what pros do (true peak <= -1 dBTP for a master, <= 0 dBTP for decoded AAC/MP3, which already holds codec overshoot). Prefer measurements, then verdicts/z/probabilities; never present cosine as confidence.
