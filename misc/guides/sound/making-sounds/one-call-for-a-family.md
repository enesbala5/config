# Make a whole family in one call

**Feeds stage:** making-sounds

Several sounds that belong together (an interface, a game, a film kit) are ONE call, never a loop of `make`. Ready-made sets: `earshot make --set ui|game|arcade|film -o FOLDER --format webm,mp3 --sprite sprite` (MCP `make_set`). `ui` has 17 roles, all things a hand does, no instrument (tap, hover, toggle_on/off, type, next/back, open/close drawer, send, receive, notify, success, complete, warning, error, delete); a plain request for one of those jobs gets the same design. `game` has 22, `arcade` 16 chip sounds, `film` 17 motion-design sounds. The game set's jump, land, hit, explosion and door are invented: where a real sound matters, name a learned one in a spec (`{"name": "door", "sound": "door/shut"}`). A spec is your own list in a JSON file — `{"sounds": [{"name": "tap", "want": "a soft tap"}, ...]}` — rendered with `earshot make --spec FILE -o FOLDER`; fields include name, want, sound, recipe, pitch, dur, voice, material, seed, n, axes, lufs, events, loop, and an unknown field is an error listing them. `"set": "ui"` adds your entries to the set (same name replaces it); without `set` only your list is made — the call for the handful a landing page or a scene needs. Every one-shot is as loud as made alone, within 2.5 dB of the others; loops and beds are levelled by kind. A re-run rewrites the files and `manifest.json` but does not delete files of names you removed. Scale to remember: the catalogue holds 922 designs in 384 families; 309 are learned from 692 public-domain recordings and no audio file is stored in the repository — every sound is rendered by code when it is asked for. The whole catalogue is playable on the earshot site in a browser.
