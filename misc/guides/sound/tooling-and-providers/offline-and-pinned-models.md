# Offline mode uses pinned models from a local cache

**Feeds stage:** tooling-and-providers

The two listening models are pinned: CLAP `laion/larger_clap_general` @ `16c8cc3` and the AudioSet tagger `MIT/ast-finetuned-audioset-10-10-0.4593` @ `f826b80`, with safetensors weights. First use downloads about 1.1 GB (about 2.2 GB on disk) into `.cache/hf` inside a clone, `~/.cache/earshot/hf` otherwise (or `EARSHOT_HOME`); after that earshot loads only from that cache and never contacts the Hub. A damaged cache is an error naming the folder, not a silent new download. `EARSHOT_OFFLINE=1`, `HF_HUB_OFFLINE=1` and `TRANSFORMERS_OFFLINE=1` all mean the same to earshot: no downloads, and a model missing from the cache is an error that says so — earshot never sets or clears them itself. `earshot doctor --fetch` downloads the models now; `--load` also reports what loads. A cache made before 0.2.1 held CLAP's pickle revision `ada0c23`; it still loads (never re-downloads) until `--fetch` replaces it with the pinned safetensors (776 MB). Settings: `EARSHOT_THREADS` (torch CPU threads, default min(4, cores/2)), `EARSHOT_PRECISION` (bf16 on CPUs with native bf16 such as AVX512-BF16 or AMX, fp32 elsewhere; `fp32` forces it), `EARSHOT_CLAP`/`EARSHOT_AST` and their `_REVISION` variants.
