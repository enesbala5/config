# Rules: diagnosis

What must be true before any recommendation is made. Loaded by `audit`, and by
`plan` when an activation/monetization design decision needs a diagnosis.

- **Context before prescription.** Identify the surface type, primary conversion
  goal and traffic source before recommending.
  Evidence: `<config>/misc/guides/conversion/page-conversion/diagnose-before-recommending.md`
- **Read existing context first.** Check marketing docs and the product-marketing
  file before asking for information they already cover.
  Evidence: `<config>/misc/guides/conversion/page-conversion/check-marketing-context-first.md`
- **Value proposition first.** Audit value-proposition clarity before tuning
  lower-impact dimensions.
  Evidence: `<config>/misc/guides/conversion/page-conversion/value-proposition-clarity-first.md`
- **Fix the largest drop.** Map the funnel with per-step percentages and direct
  effort at the largest drop, not the easiest step.
  Evidence: `<config>/misc/guides/conversion/activation/find-the-biggest-funnel-drop-off.md`
- **Structured findings.** Report each issue as finding, impact, recommendation
  and priority.
  Evidence: `<config>/misc/guides/conversion/activation/structure-onboarding-audit-by-finding-impact-recommendation-priority.md`
- **Upgrade context before paywall advice.** Establish upgrade context, product
  model, user journey and the product's aha moment before advising on a paywall.
  Evidence: `<config>/misc/guides/conversion/monetization/diagnose-upgrade-context-before-recommending.md`
