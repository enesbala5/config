# Rules: acquire

How a sound is obtained, read and handed over. Driven by the `making-sounds` and
`building-sounds` buckets. Evidence pointers name lessons; the prose stays in the guide.

- Name the sound itself before any call; its intended use is not a description of it.
  Evidence: `<config>/misc/guides/sound/listening/write-queries-describe-sound-not-use.md`
- A catalogue id that is only the nearest match is not the requested thing. Build
  the thing or say it is missing; never deliver the stand-in as the answer.
  Evidence: `<config>/misc/guides/sound/making-sounds/the-makes-no-line-is-the-only-warning.md`,
  `<config>/misc/guides/sound/building-sounds/build-when-catalogue-lacks-the-thing.md`
- The whole answer is read and every warning line acted on; a result other than
  `clean` is remade, not handed over.
  Evidence: `<config>/misc/guides/sound/making-sounds/read-the-whole-answer.md`
- Hit placement is computed from the reported peak offset; the sound file's clock
  is not the timeline's clock, and file placement belongs to a separate editor.
  Evidence: `<config>/misc/guides/sound/making-sounds/place-the-hit-with-peak-s.md`
- A build is accepted on fit plus a clean second-ear check, not on a good written
  description; a "sketch" verdict stays a sketch.
  Evidence: `<config>/misc/guides/sound/building-sounds/fit-and-second-ear.md`
- Absence of artefacts is not identity: say what a build is made from and that a
  person should listen once.
  Evidence: `<config>/misc/guides/sound/building-sounds/cookbook-clean-is-not-identity.md`
